# Zenoh 迁移任务包

本目录把多传感器平台拆成可以独立分配的任务。总体设计见 `设计/zenoh采集架构/README.md`。

## 使用规则

每个任务文件夹都是一份交付合同，实施者必须：

1. 先阅读 `00-contract-and-benchmark` 输出的固定版本、key/schema 和性能基线；
2. 不直接修改其他任务的内部实现，通过 `03-common-sdk` 契约集成；
3. 提供 Docker 镜像、配置示例、mock 模式、单元测试和验收报告；
4. 不以“进程未崩溃”代替性能或数据正确性测试；
5. 真机无法接入时可以完成 mock/回放测试，但必须把真机验收项标为待执行，不能宣称通过；
6. 所有运行依赖固定版本或 digest，禁止生产配置使用 `latest`；
7. 发现契约不够时先提交 ADR，不能在单个驱动里发明另一套 key 或消息头。

## 统一交付目录

各任务落地代码时使用以下目标目录：

```text
src/
├─ common/                 # 03
├─ platform/
│  ├─ router/             # 01
│  ├─ console-api/        # 02
│  ├─ console-web/        # 02
│  └─ observability/      # 10
├─ pub_server/
│  ├─ gige-camera/        # 04
│  ├─ lidar/              # 05
│  ├─ imu/                # 06
│  └─ plc/                # 06
└─ sub_client/
   ├─ foxglove/           # 08
   ├─ recorder/           # 09
   └─ examples/           # 03/09
```

`resource/` 是迁移输入和参考实现，不在未完成回归测试前删除。

## 通用验收证据

每个任务的 PR 至少附：

- 测试命令与输出；
- 使用的 CPU、内存、NIC、Zenoh/镜像版本；
- mock 或真机标记；
- 已知限制；
- 配置样例；
- 对外接口变更；
- 对应指标截图或机器可读基准结果。
