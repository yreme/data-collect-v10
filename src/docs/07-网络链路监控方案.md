# 07 网络链路监控方案（替代 gige_discover.py）

## 1. 旧方案为何与采集冲突

`resource/pub_server/gige-camera-sync/scripts/gige_discover.py` 通过 `arv-tool-0.8 -a <ip> control GevLinkSpeed ...` 读取参数。
`arv-tool control` 会**打开设备并申请控制权限（CCP 寄存器）**，而采集进程（MVS 默认 `MV_ACCESS_Exclusive`）已独占控制通道：

* 采集运行时：arv-tool 失败/超时；
* 先运行 arv-tool：采集进程打开设备失败，或心跳被打断导致掉线重连。

GigE Vision 规定同一时刻只能有一个控制者，因此**任何"另开一个进程去读相机寄存器"的方式都会冲突**。

## 2. 新方案：三层，互不干扰

| 层 | 谁来做 | 获取方式 | 是否接触相机控制通道 | 得到的信息 |
| --- | --- | --- | --- | --- |
| L1 采集进程自报（**主方案**） | `pub-camera-gige` | 用**已打开的句柄**周期读取 `GevLinkSpeed`/`DeviceLinkSpeed`（每 `link_check_interval_sec` 秒，MVS `MV_CC_GetIntValue`）；同时统计读寄存器往返时间作为控制通道延迟 | 是（自己的句柄，无冲突） | 协商速率、控制通道 RTT、温度、丢包重传计数（`GevStreamChannel` 统计）、帧延迟 |
| L2 netprobe 被动探测 | `pub_server/netprobe`（任务 T06） | ① GVCP **DISCOVERY** 广播（UDP 3956，任何时候都允许，不需要控制权） ② ICMP ping RTT ③ 主机网卡 `/sys/class/net/<if>/speed` ④ 交换机 C 的 SNMP `IF-MIB::ifHighSpeed` / `ifOperStatus` / `ifInErrors`（按端口） | 否 | 在线设备列表（ip/mac/型号/序列号）、网络 RTT、交换机端口协商速率（**相机/雷达侧实际链路速率**）、误码 |
| L3 MVS 监视模式（可选） | 诊断脚本 | `MV_CC_OpenDevice(handle, MV_ACCESS_Monitor)` 只读打开 | 只读，不抢控制权 | 采集进程不支持 L1 时的兜底 |

L2 是"简单不打扰"的方式：交换机端口速率就是相机实际协商速率（百兆降速会直接体现为 `ifHighSpeed=100`），
不需要碰相机，也同样适用于雷达、IMU 网口等所有接在交换机 C 上的设备。需要交换机开启 SNMP v2c（只读 community）。
没有网管交换机时，L1（相机）+ 雷达 DIFOP 包中的状态信息即可覆盖。

## 3. 数据流与展示

* L1：随相机 `status.device` 发布：`link_speed_mbps`、`expected_link_mbps`、`rtt_ms`、`ctrl_rtt_ms`。
  低于期望速率时 pub `set_state("degraded", "link 100Mbps")` 并发事件。
* L2：netprobe 以 1Hz 在 `rig/net/netprobe/links` 发布 JSON：

```json
{"ts_ns": 0, "links": [
  {"ip": "192.168.1.101", "mac": "34:bd:20:..", "model": "MV-CA023-10GC", "serial": "DA0849311",
   "source": ["gvcp", "icmp", "snmp"], "rtt_ms": 0.21, "loss_pct": 0,
   "switch_port": "Gi1/0/3", "port_speed_mbps": 1000, "port_errors": 0,
   "sensor": "camera/cam_corner_0"}
]}
```

  `sensor` 字段由 netprobe 依据 `sensors.yaml` 中的 serial/ip/mac 匹配。
* 控制台"网络链路"页：合并 L1+L2，按传感器显示协商速率（与期望不符标红）、RTT 曲线（动态刷新）、交换机端口、误码；
  "总览"页每个相机显示链路速率徽标与帧延迟 `latency_ms`。

## 4. 相机动态控制（控制台"传感器控制"页）

| 功能 | 参数 | 生效方式 |
| --- | --- | --- |
| 频率 10→5→1Hz | `hz` | 网格在下一个整秒切换；软件触发/Action 模式下相机无需停流 |
| RGB / Mono 切换 | `pixel_format`（相机侧）+ `publish_encoding`（总线侧） | `pixel_format` 需停流 → `PixelFormat` → 重新开流（约 0.5–1s），pub 内部完成；帧大小随之变化（status 中 `msg_bytes`） |
| 曝光 | `exposure_auto`、`exposure_us`、`gain_db` | 在线写 GenICam 节点，下一帧生效 |
| 网络延迟 | 只读：`rtt_ms`、`ctrl_rtt_ms`、`latency_ms` | 1Hz 刷新 |

控制台通过 `ctrl` → `set_params` 下发，返回 `applied`/`restart_required`/`effective_ns`，结果在事件页可追溯。
