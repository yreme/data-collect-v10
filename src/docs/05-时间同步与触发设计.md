# 05 时间同步与触发设计

实现：`common/python/sensorhub/sync_grid.py`（`GridTimer`、`nearest_slot`）、`sub.SyncAssembler`。

## 1. 核心思想：确定性全局网格

```
slot_k = k × period_ns + phase_ns      （Unix ns；period = 1e9 / hz）
```

* 频率必须整除 1 秒（1,2,4,5,8,10,20,25,40,50… 或 0.5/0.2/0.1Hz），所以**每个整秒都是网格点**，
  20Hz 网格 ⊇ 10Hz ⊇ 5Hz ⊇ 1Hz。相机 20Hz、雷达 10Hz 时，雷达每一帧都与某一相机帧同网格时刻。
* 每个 pub 进程**独立**根据本机时钟计算网格，不需要相互通信 —— 因此**独立 docker 容器、甚至不同服务器之间**都能同步，
  前提只有一个：**主机时钟同步**（同一台服务器内天然满足；A/D 之间用 PTP 或 chrony，误差 < 0.1ms/1ms）。
* 频率变更（10→5→1Hz）在**下一个整秒**生效：控制台同时向多个实例下发 `set_params{hz}`，各自在同一整秒切换，不会错拍。
* `sync-master`（任务 T05）只负责发布 `rig/sync/master/schedule`（当前网格计划 + 生效时间）并监控各传感器 `sync_err_ms`，
  **它挂了不影响采集**（各 pub 仍按本地网格运行）。

## 2. 各类传感器的同步方式

| 传感器 | 方式（优先级从高到低） | flags | 期望误差 |
| --- | --- | --- | --- |
| GigE 相机 | ① 硬件触发线（外部脉冲发生器/PLC 按网格输出） ② **GigE Vision Action Command**：相机开启 PTP（`GevIEEE1588`/`PtpEnable`），主机提前 ≥5ms 发送 `ActionTime=slot_ns` 的计划动作，所有相机在同一 PTP 时刻曝光 ③ 软件触发：采集线程在 `slot` 时刻对每路相机发 `TriggerSoftware` | bit0 / bit1+bit4 / bit2 | ① <10µs ② <50µs ③ 0.2–2ms（受调度抖动影响） |
| 速腾雷达 | 雷达开启 PTP/gPTP（或 GPS+PPS）授时，配置**相位锁定**（phase lock，使雷达在每个整秒/网格时刻扫过指定方位角），转速 600rpm=10Hz 与网格对齐；stamp 用雷达自带时间戳 | bit3+bit4 | <1ms（取决于型号） |
| IMU | 一般不支持外触发：以主机接收时刻打时间戳（或设备自带时间并做偏差估计），按 `publish_hz` 网格把 `(slot-period, slot]` 内的全部样本打成一批发布，`trigger_ns=slot` | bit5 | 样本级时间戳，批次与网格对齐 |
| PLC | 按收到时刻打时间戳，原始频率发布（或按网格合并最新值） | bit5 | — |

相机使用软件触发时，触发命令必须由**同一个进程**对所有相机并行发出（每路一个线程，在 `GridTimer.wait_next()` 返回后立即触发），
`GridTimer` 使用 sleep + 最后 `spin_ns`（默认 0.3ms）忙等，降低唤醒抖动；容器加 `SYS_NICE` 后可用 `SCHED_FIFO`。

Action Command 在 MVS SDK 中：`MV_GIGE_IssueActionCommand`（`nDeviceKey/nGroupKey/nGroupMask/bActionTimeEnable/nActionTime`），
相机侧设置 `TriggerSource=Action1`、`ActionDeviceKey/ActionGroupKey/ActionGroupMask`。需要相机 PTP 已锁定（`GevIEEE1588Status=Slave`），
并且主机 PTP（`linuxptp ptp4l`）作为 master 或与同一 grandmaster 同步。

## 3. 时间戳字段

* `trigger_ns`：网格时刻（理论曝光/扫描时刻）——**对齐用这个**。
* `stamp_ns`：传感器实际时刻（相机曝光开始，雷达首点，IMU 样本）。
* `sync_err = stamp_ns - trigger_ns`：pub 端统计后在 status 中给出 `sync_err_ms{p50,p95,max}`，控制台显示。
* `pub_ns`：发布时刻；`latency = pub_ns - stamp_ns`（采集+传输到主机+处理），`sub 接收 - pub_ns` 为总线传输延迟。

## 4. 消费端对齐

`SyncAssembler(required, base_hz)` 按 `nearest_slot(trigger_ns or stamp_ns, period(base_hz))` 分组；
`base_hz` 取各传感器频率的公共频率（相机 20 + 雷达 10 → 10）。超时 `timeout_s` 后输出不完整组（`emit_partial`）或丢弃。

## 5. 验收方法

1. 软件触发：6 路相机 20Hz 运行 10 分钟，`sync_err_ms.p95 < 2`，同一网格时刻各路 `stamp_ns` 跨度 p95 < 2ms。
2. Action Command：同上，跨度 p95 < 0.1ms。
3. 拍摄同一块毫秒计时屏（或 LED 阵列）验证实际曝光一致性。
4. 在线把频率 20→5→1→20，检查各路在同一整秒切换、`seq` 无异常断档、同步组完整率不变。
